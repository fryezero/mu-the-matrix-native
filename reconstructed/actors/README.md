# Actor routines (NATIVE-ACTOR-001)

Authored C for the client routines that give monsters and NPCs their models and action speeds and that drive
the animation tick. See [the finding](../../docs/research/client-actors.md).

| File | Content | Evidence |
|---|---|---|
| `actors.c`, `actors.h` | `mu_monster_open` (OpenMonsterModel `0x0180b0f4`), `mu_character_animation_step` (`0x013960d2`), `mu_set_action` (`0x012affa4`), `mu_player_unarmed_stop_action` (`0x0139d6da`), table lookups, the static pose mapping | Compared with the client under Unicorn (`scripts/validate_actors.py`); pose mapping static |
| `monster_open_table.h` | Per-type operations of the opener's two switches | Generated by `scripts/actor_static.py` (static lifter), checked by the validator |
| `monster_class_table.h`, `npc_table.h`, `player_action_table.h` | Server class → model/scale/slots, NPC files and speeds, base Player speeds | Extracted by running client code under Unicorn (`validate_actors.py --emit-*`) |

`make` builds `libactors` (with the skinning stack, whose tick the animation step runs). `test_actors.py` holds the
portable checks and the opt-in private comparison.
